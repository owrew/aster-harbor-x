# Media Harvester Downloader 1.1

A separate local Edge extension project, based on the supplied MPL-2.0 Media Harvest 4.5.7 source.
The manifest uses 4.5.8 for upgrading the earlier fork; the project release is 1.1.0.

## Install or update

1. Back up existing DM links from Saved links → Back up all chats.
2. Extract Media-Harvester-Downloader-v1.1.zip.
3. In edge://extensions enable Developer mode and choose Load unpacked, then select the folder containing manifest.json.
4. Disable older copies of the collector/Media Harvest to avoid duplicate controls. Do not also paste a console collector.
5. Refresh X. If this new folder is a separate installation with empty storage, import the JSON backup in Saved links.

To keep the existing unpacked installation's storage, replace the files in its existing folder with this build, click Reload in edge://extensions, then refresh X. Keep a backup first. The original Downloads source was not edited.

## Downloading is independent of harvesting

Normal X video posts get a Download video button when a recognizable post permalink and video component are present. Identifiable DM cards get the same control. Incoming DM post-preview references also appear as recent post IDs with Download video buttons in the floating panel, even while harvesting is stopped.

These idle references are kept only in bounded memory for showing download controls. They are not added to a saved DM collection until you start harvesting. X's changing or encrypted interfaces may not expose a usable post ID for every thumbnail.

Download video opens a picker:

- If recovered MP4 data is available, choose Download video 1, 2, etc.
- If it is unavailable, choose Find videos. This is a deliberate network lookup through Media Harvest's native services, with a signed-in X tab open.
- Choose an individual video to dispatch it to the original Media Harvest browser/Aria2 downloader.
- Check Edge Downloads or Aria2 for completion. Dispatched does not mean the transfer completed.

The saved-links library also has a Download video button beside every post. Private, deleted, inaccessible, expired, or non-MP4 media can fail. Directly uploaded DM videos without an underlying post ID are not handled by this post-based downloader.

No video downloads automatically. Stop harvesting does not cancel a download you already requested; use Edge Downloads or Aria2 to cancel it.

## Start and stop

Harvesting is stopped on first load and after every refresh.

1. Open a full X DM conversation.
2. Choose Start harvesting.
3. Choose Harvest DM links to collect while scrolling manually, or Harvest older DM links to choose a scroll area.
4. For automatic older-message loading, choose the message area and explicitly press Start slow scroll.
5. Stop harvesting stops link saving and automatic scrolling. Download controls remain available.

Saved collections survive refresh and remain deduplicated by conversation ID and post ID. After refresh you must start again. Download-button detection continues as lightweight passive observation so the controls remain available.

## Settings

Use Settings in the floating panel, Download settings in the picker, or the original extension popup/settings page.

Existing Media Harvest settings are retained, including filename templates, Save As prompts, download history, and Aria2 integration. A single recovered video without full post metadata uses a deterministic filename: Media Harvester/postID_videoN.mp4. Videos found through Media Harvest's full lookup use its filename template.

The current picker offers the highest-bitrate recovered MP4 per video; it does not yet offer a resolution/bitrate selector.

## Rate limits and collection scope

Automatic scrolling remains at most one partial-viewport step per 15 seconds, capped at 50 steps per session. It stops on a relevant limit or access error, conversation changes, hidden tabs, or lack of movement. A 429 cooldown uses readable retry/reset headers, otherwise a 15-minute fallback. Upstream lookup quota errors also pause further Find videos actions.

Do not keep scrolling or repeatedly refreshing while X is limiting you. The extension cannot prevent X's own requests, guarantee an account will not be restricted, or bypass server limits.

Only the selected DM is eligible for saved link collection. Known mismatched conversation responses are rejected. A background post lookup that omits conversation metadata can still be ambiguous, so exact message-level attribution and complete history coverage are not guaranteed.

## Existing collection features

Conversation selector, search, TXT/CSV exports, JSON backup/restore, encoded-URL decoding, readable DM archive import, minimized panel, and saved partial checkpoints are retained. Archive imports execute no code and upload nothing.
