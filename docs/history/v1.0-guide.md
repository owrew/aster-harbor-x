# DM Link Vault — Edge installation and use

## Choose a package

- **Media-Harvest-DM-Vault.zip**: the supplied Media Harvest extension, rebuilt with the DM collector added. Its original popup, download controls, filename settings, download history, and Aria2 integration code are retained. The DM panel’s **Saved links** button opens the new library.
- **DM-Link-Vault-Standalone.zip**: the collector alone, with fewer permissions. Use this if you already have Media Harvest installed. Do not install both collector packages at once.

The original Downloads folder was not modified. The combined package retains its Mozilla Public License 2.0 notices. The collector is local and adds no cloud service. Upstream cloud/premium services require credentials that were not supplied. Native media downloading remains subject to X access and upstream behavior.

## Install

1. Extract the chosen ZIP into a permanent folder.
2. In Edge open edge://extensions, turn on **Developer mode**, and select **Load unpacked**.
3. Select the extracted folder containing manifest.json.
4. Refresh X. Do not run an older console collector alongside the extension.
5. Open a full conversation whose URL includes its conversation ID, for example /i/chat/… or /messages/….
6. Choose **Collect this DM** in the floating panel.

Microsoft’s installation instructions: https://learn.microsoft.com/en-us/microsoft-edge/extensions/getting-started/extension-sideloading

## Persistence and scope

Links are saved in local extension storage, indexed by conversation ID plus post ID. A refresh preserves links and the tab’s selected conversation. Seen posts are not added again. A browser restart retains links, but requires selecting a DM again to avoid reusing an old tab’s session. Moving to another DM pauses collection until you explicitly select it.

Only post URLs, post-specific fields, and typed Tweet objects authorize links. Generic user, message, and media IDs are not converted into posts. Even a rate-limited GetPostById response can identify the requested post from the request’s explicit rest_id; no retry is needed.

The extension watches page requests and readable loaded DM elements. It does not replay requests, bypass encryption, request passwords, or read the system clipboard. Use the paste field for links copied from X’s preview menu.

Collection is accepted only while the top-level page is the selected DM. Responses tagged with another conversation are rejected. Ambiguous inbox-wide responses without a matching conversation ID are skipped.

A post lookup issued while the selected DM is active is attributed to that DM; unrelated background prefetches within that same view cannot be definitively distinguished. Strict attribution to a specific message cannot be guaranteed without a matching conversation field or live validation.

## Older-message scrolling

1. Choose **Choose message area**.
2. Click inside the actual message history.
3. Choose **Start slow scroll**.

It scrolls upward by part of a viewport once every 15 seconds, with at most 50 steps per session. It stops when the selected DM changes, the tab becomes hidden, the message area disappears, a rate limit occurs, five steps produce no movement, or you press Stop. The saved checkpoint records partial progress, not X’s private history cursor.

After refresh, reselect the scrolling area and start manually. Already-saved links stay deduplicated, though X itself may request the same preview again. The extension does not block X’s requests or automatically replay scrolling.

## Rate limits

On HTTP 429, automatic scrolling stops. A persisted cooldown uses readable Retry-After / x-rate-limit-reset headers, with a 15-minute fallback. HTTP 403 stops scrolling with a 30-minute fallback; it may indicate an access problem rather than a temporary limit. Restart manually after checking the page.

This controls the extension’s scrolling, not requests made by X itself, manual scrolling, or another extension. It cannot guarantee that your account will never be restricted. Avoid rapid refreshes or continued scrolling during an active rate limit.

X’s public API guide: https://docs.x.com/x-api/fundamentals/rate-limits
Those documented limits do not establish the quotas of X’s internal GetPostById endpoint.

## Library and backups

Choose **Saved links** to select a conversation, search by post ID/source, copy filtered links, export TXT/CSV, or back up all chats to JSON. Recipients still need access to private/protected or unavailable posts.

The library offers recovered media URLs when present in a typed post response. Opening a saved post lets you use Media Harvest’s existing download controls in the combined package. No bulk downloader is automatically launched.

Back up before uninstalling, changing profiles, or replacing a standalone extension with the combined build: separate installations have separate storage. Import the backup into the new installation.

## Offline archive import

X says its archive includes Direct Messages:
https://help.x.com/en/managing-your-account/accessing-your-x-data

Request and extract your archive. In the library, expand **Import a backup or X archive** and select direct-messages.js, direct-messages-group.js, or a Vault JSON backup. Assignment wrappers are removed and JSON is parsed locally; scripts are never executed. Each supported archive conversation gets a separate collection. Files over 100 MB are rejected.

Import recovers post links present in readable message text/entities. It cannot recreate deleted messages or decrypt Chat export formats. Check the actual archive rather than assuming full encrypted-chat coverage:
https://help.x.com/en/using-x/about-chat

## Validation boundary

This is an unpacked local extension, not a signed store release. Tests use an isolated Edge profile and simulated X pages/responses; they do not access your account. Live X rendering, encrypted Chat variants, exact message attribution, full-history coverage, and actual media-download availability require user-side verification. No complete-conversation claim is made.
