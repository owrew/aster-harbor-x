# Media Harvester Downloader 1.2

This release includes all v1.1 DM link collections, individual-video controls, exports, backup/import, and manual Start/Stop behavior, with a redesigned interface and less idle work.

## Install or update

Back up your saved links first. Extract Media-Harvester-Downloader-v1.2.zip, open edge://extensions, enable Developer mode, and Load unpacked the directory containing manifest.json. Refresh X.

For an existing unpacked installation, replacing its files in the same folder and choosing Reload preserves that extension's storage. A separately loaded folder can receive a different extension ID and will need your JSON backup imported. Disable older collector copies.

The extension's project version is 1.2.0. Its manifest version is 4.5.9 to upgrade the earlier Media Harvest fork.

## Interface and controls

- A new compact popup opens the library, download activity, settings, and in-page harvesting-mode chooser. Stop is available from both popup and panel.
- The in-page panel groups advanced scrolling and manual capture in a collapsible section.
- Library navigation includes conversation filters, search, sorting, comfortable/compact list layout, selection, copy-selected, and confirmed removal of selected saved links. Removal never deletes video files. One removal accepts at most 2,000 links.
- Download activity distinguishes dispatch from completion. Check Edge Downloads or Aria2 for actual transfer status.
- Light, dark, and system themes use local fonts and no remote font resources.

Download video buttons stay available while harvesting is stopped, where a post ID can be identified. A video picker lets you choose one video. Find videos is an explicit lookup through Media Harvest, not an automatic background action.

## Settings

Choose panel position and compact layout; enable/disable post download buttons and idle DM preview-reference detection. Turning preview detection off does not disable explicit link harvesting.

Performance controls allow 400–3,000 ms debounce, 50–400 inspected cards per change, 15–120 seconds between scrolling steps, and 10–200 steps per session.

Media Harvest download settings still provide filename templates, Save As, history, and Aria2 options. The new settings page opens the original advanced page only when requested. Legacy in-page keyboard shortcuts and duplicate legacy observer controls are not loaded in this lightweight build; use the new buttons.

An optional creator-support URL stays blank until you have an approved provider page. It opens externally from the popup; no payment scripts or trackers are loaded into X. See Oman-Creator-Payout-Options.md.

## Performance changes

- Removed the collector's 2.5-second polling loop.
- Mutation-driven, debounced scans; no collector DOM scans while a tab is hidden.
- Small scoped summary reads instead of loading every conversation into the X panel.
- Duplicate observations do not rewrite unchanged saved records.
- Removed the legacy 273 KiB main page observer from the active content-script manifest. Media Harvest's native worker and advanced settings remain.
- A small transaction-ID helper supports user-requested lookups; it does not scan message history.
- Default popup and settings no longer load the original React settings bundle; the advanced original page remains user-opened.

The active page-script file total was 325,375 bytes in v1.1 and is about 54 KB in v1.2. This is uncompressed static JavaScript size, not a measured RAM or CPU reduction. In a stable isolated fixture, the collector sent zero worker messages during a four-second idle observation.

The backend is still a Manifest V3 worker with Media Harvest's native services; normal browser scheduling and upstream tasks can wake it. No claim of zero CPU, universal low-end-device performance, or zero X overhead is made.

## Start/stop and privacy

Harvesting starts stopped, including after refresh. Open a full DM conversation, choose Start harvesting, then choose a mode. Older-message scrolling additionally requires selecting the actual message area and starting slow scroll.

Stop halts link collection and automatic scrolling. Manual video downloads and lightweight download-button detection remain independent. Use the detection switches to reduce idle processing further.

Saved post links remain deduplicated and separated by conversation. Known mismatched conversation responses are rejected; post lookups without conversation metadata can still be ambiguous. Neither complete history capture nor perfect attribution to individual messages is guaranteed.

HTTP rate-limit cooldowns are retained. The extension does not bypass X limits or stop X itself from issuing requests. Reaching a scroll boundary does not establish that the full conversation was collected.

## Validation

Production content-script compilation passed. The inherited native worker was built and type-checked for v1.1; its download bridge is unchanged in this release.

Isolated Edge tests passed default stopped behavior, explicit Start/Stop, individual-video dispatch through Media Harvest with the browser download API mocked, conversation separation, persistence, iframe scrolling, cooldowns, archive import, export, settings persistence, themes, selection/removal, page rendering, idle-storage observation, and disabling detection without reloading X.

Actual video bytes, live-account authorization, uncached lookup success, Aria2 transfers, encrypted Chat variants, and low-end hardware load were not validated.

The supplied original Downloads source is unchanged. MPL 2.0 notices, modified source, and reproducible integration scripts are included in the source package. Upstream cloud/premium services remain unconfigured because credentials were not provided.
